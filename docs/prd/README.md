# PRD 스냅샷 보관소

설계 결정의 **히스토리**를 남기는 곳. 각 PRD는 작성 시점의 스냅샷이다.

## 규칙
1. 파일명: `PRD-XXXX-<kebab-제목>.md` (번호는 4자리, 순차 증가)
2. **작성 후 본문 수정 금지.** 설계가 바뀌면 새 PRD를 쓰고, 이전 PRD 상단 표의 `상태`를 `대체됨 → PRD-YYYY`(일부만 바뀌면 `일부 대체됨 → PRD-YYYY`)로만 바꾼다.
3. 현재 유효한 정책은 PRD가 아니라 [CONSTITUTION.md](../CONSTITUTION.md)에서 확인한다. PRD에서 확정된 내용은 헌법에 반영한다.
4. **작성 단위:** PRD는 **기능 단위**로만 작성한다: 새 기능이나 흐름의 큰 재설계일 때 1개. 같은 기능을 다듬는 연속 수정(문구·배치·옵션 추가·버튼 제거 등)은 PRD를 새로 쓰지 않고, 헌법 갱신 + 커밋 메시지로 남긴다. 다듬기가 쌓여 기능 설계가 크게 달라졌으면 그때 그 기능의 PRD를 하나로 정리해 새로 쓴다.
   - 문서별 역할: PRD = 기능 설계의 이유(왜) · 헌법 = 지금 유효한 규칙(무엇) · 커밋 = 세부 변경 이력(언제·어떻게)
   - (참고) PRD-0009~0014는 이 기준 이전에 붙이기 기능을 요청 건마다 나눠 쓴 것으로, 스냅샷 원칙에 따라 그대로 둔다.
