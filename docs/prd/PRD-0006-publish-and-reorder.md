## 1. 배경
- 편집기 헤더에 문서 제목·저장 상태·하객 화면 보기·공유하기가 섞여 있어 주요 행동이 흐려졌다.
- "청첩장 제목"이 기본 정보 안에 있었다. 그런데 제목은 기본 정보(이름·날짜·장소)라기보다 **공유(발행) 정보**에 가깝다.
- 순서 변경이 위/아래 화살표 클릭이라 여러 칸을 옮길 때 번거롭다.
- 숨긴 섹션에 `숨김` 배지와 줄긋기가 같이 표시되어, 스위치와 중복된 시각 신호가 많았다.

## 2. 결정
| # | 영역 | 결정 |
|---|---|---|
| D1 | 시작 방법 | 선택한 템플릿 정보(썸네일·이름) 삭제 |
| D2 | 편집기 데스크탑 | 헤더의 문서 제목·`저장 안 됨 (준비 중)` 삭제 |
| D3 | 편집기 데스크탑 | `하객 화면 보기`·`공유하기` 삭제 → `미리보기` 하나로 |

| D5 | 편집기 모바일 | 하단 툴바의 `공유` 삭제 → `구성`·`기본 정보`만 |

| D8 | 청첩장 만들기 | 입력 항목: **청첩장 제목**(기본 정보에서 이동, 비우면 자동), **링크**(자동 입력, 수정 가능) |

## 3. 설계 세부
### 3.1 청첩장 만들기
- 모바일은 바텀시트, 768px 이상은 같은 컴포넌트를 CSS로 가운데 대화상자로 표시한다.
- **제목**: `doc.title`이 비어 있으면 `<신랑> ♥ <신부> 결혼합니다`로 표시된다. 저장된 값이 아니라 그때그때 계산하므로 이름을 바꾸면 따라 바뀐다. 기존에는 생성 시점에 문자열로 고정되어 이름을 바꿔도 제목이 그대로였는데, 그 문제도 함께 해결된다.
- **링크**: `<사이트 호스트>/i/<slug>`.
  - 기본값은 `<예식일 YYYYMMDD>-<랜덤 4자>`다. 예식일만 쓰면 같은 날 결혼하는 커플끼리 겹치므로 랜덤을 붙였다.
  - 한글 이름을 로마자로 바꾸는 방식은 표기가 일정하지 않아(예: 이 → lee/yi/rhee) 쓰지 않았다.
  - 입력 중 정규화(소문자·공백→`-`·허용 문자만·연속 `-` 축약), 포커스 해제·제출 시 검증(3자 이상, `-`로 시작/끝 불가).
- **제출**: 서버가 없으므로 실제 발행은 하지 않고 안내만 띄운다. 중복 검사와 `/i/<slug>` 하객 페이지는 서버 도입 시 구현한다.

### 3.2 드래그 앤 드롭
- HTML5 Drag and Drop은 모바일 터치에서 동작하지 않으므로 **포인터 이벤트로 직접 구현**했다(외부 라이브러리 없음, 헌법 §9.1).
- 손잡이를 누르면 각 행 위치를 측정한다. 끄는 동안 대상 행은 손가락/커서를 따라가고, 나머지 행은 들어갈 자리만큼 비켜난다. 놓을 때 한 번만 상태에 반영한다.
- 히어로 고정 규칙(§4.2-2)은 리듀서의 `REORDER_SECTION`이 강제한다(목표 위치를 1 이상으로 제한).
- 키보드 대안: 손잡이 포커스 후 ↑/↓.

## 5. 열린 질문
- 실제 발행 도메인과 `/i/<slug>` 하객 페이지 구조(서버 렌더링·OG 메타)
- 링크 중복 시 처리(자동 접미사 vs 사용자에게 수정 요청)
- 드래그 중 목록이 화면 밖으로 길어질 때 자동 스크롤 필요 여부(현재 8개 섹션이라 미구현)
