# PRD-0010 붙이기 흐름 단계 분리

| 항목 | 내용 |
|---|---|
| 상태 | **확정 (스냅샷)** — 이 문서는 수정하지 않는다. 변경은 새 PRD로. |
| 작성일 | 2026-10-13 |
| 관련 헌법 | CONSTITUTION v0.12 (§4.10) |
| 대체 | PRD-0009 §2 사용자 흐름 (① 사진·프레임을 한 화면에서 고르던 방식) |

---

## 1. 배경
PRD-0009의 1단계는 한 시트 안에 세 가지가 섞여 있었다.
- 사진 올리기 영역
- 올린 사진 목록
- 프레임 선택

`붙이기`를 누른 뒤 무엇을 먼저 해야 할지 한 번 더 판단해야 했고, 화면이 길어 모바일에서 스크롤이 생겼다.

## 2. 결정
| # | 결정 | 이유 |
|---|---|---|
| D1 | `붙이기` → **기기 사진 선택 창을 바로 호출** (중간 시트 없음) | "내 사진을 붙인다"는 행동과 첫 화면이 일치. 단계 하나 줄어듦 |
| D2 | 사진을 고른 뒤에야 시트가 열리고, **프레임 단계**부터 시작 | 프레임을 고를 때 이미 내 사진이 들어가 있어 결과를 바로 비교 |
| D3 | 프레임 단계는 **단독 화면**: 큰 미리보기 + 4종 카드(내 사진이 각 모양으로 잘린 모습) | 모양을 글자가 아니라 결과물로 비교 |
| D4 | 이미 올린 사진에서 고르는 목록은 제거 | 흐름 단순화. 다른 사진은 사진 선택 창에서 다시 고르면 됨 |
| D5 | 사진 선택 창을 닫으면 아무 화면도 열지 않음 | 취소 의도를 그대로 존중 |
| D6 | 수정은 프레임 단계에서 시작, `사진 바꾸기`(선택 창 호출)·`위치만 옮기기` 제공 | 수정 시에도 같은 단계 구조 유지 |
| D7 | 단계 표시 `1. 사진 ✓ · 2. 프레임 · 3. 움직임 · 4. 위치`, 위치 바에도 `4. 위치` 표기 | 지금 몇 단계인지 항상 보이게 |
| D8 | 선택을 빠르게 연달아 눌러도 마지막 값이 저장되도록 최신 상태를 ref로 읽음 | 테스트 중 "움직임 선택 직후 바로 위치 정하기" 시 이전 값이 저장되는 버그 발견 → 수정 |

## 3. 흐름
```
[붙이기] ─▶ (기기 사진 선택 창) ─┬─ 취소 → 아무 일 없음
                                └─ 선택 → ② 프레임 ─[다음]▶ ③ 움직임 ─[위치 정하기]▶ ④ 위치(섹션 위) ─[완료]▶ 붙음
                                                  ◀[이전]─
붙은 스티커 탭 → ② 프레임(수정) : [사진 바꾸기] [위치만 옮기기] [다음] · 이 스티커 떼기
```

## 4. 참고
- 브라우저는 사용자 동작(클릭) 안에서만 파일 선택 창을 열 수 있다. 그래서 `붙이기` 클릭 처리 안에서 바로 호출한다.
- 사진 수 제한(30장)에 걸리면 선택 창을 열지 않고 안내만 한다.
