# PRD-0002 결혼식 전용으로 타겟 축소

| 항목 | 내용 |
|---|---|
| 상태 | **확정 (스냅샷)** — 이 문서는 수정하지 않는다. 변경은 새 PRD로. |
| 작성일 | 2026-10-13 |
| 관련 헌법 | CONSTITUTION v0.2 (§1.1, §1.2, §1.3, §1.4, §2, §3.4, §5.1, §6.2 개정) |
| 대체 | PRD-0001 중 "행사 종류(결혼식/돌잔치/파티)" 관련 범위 |

---

## 1. 배경
PRD-0001은 확장성을 위해 결혼식·돌잔치·파티 3종을 지원하고, 시작 시 "어떤 초대장을 만들까요?"를 묻는 분기를 두었다.
현 단계의 실제 타겟은 **결혼식(모바일 청첩장)뿐**이다. 쓰이지 않을 선택지는 사용자에게 한 단계를 더 요구하고, 코드에는 행사별 분기를 남긴다.

## 2. 결정
| # | 결정 | 이유 |
|---|---|---|
| D1 | 행사 종류 선택 UI를 모두 제거 (쉽게 시작 1단계, 편집기 바로 시작의 선택 패널) | 타겟이 하나이므로 불필요한 단계 |
| D2 | 쉽게 시작 마법사 4단계 → **3단계** (사진 → 기본 정보 → 결과) | D1의 결과 |
| D3 | "편집기에서 바로 시작"은 클릭 즉시 기본 청첩장으로 편집기 진입 | D1의 결과 |
| D4 | 돌잔치·파티 프리셋과 행사별 분기 코드 삭제, 청첩장 기본값은 `WEDDING` 하나로 | 쓰이지 않는 코드 제거 |
| D5 | 문서의 `eventType` 필드는 `'wedding'` 고정값으로 **유지** | 저장된 초안 스키마 호환 + 나중에 타 행사를 다시 붙일 때 마이그레이션 비용 최소화 |
| D6 | 섹션 이름은 결혼식 용어로 고정 ("혼주", "신랑/신부에게 할 말") | 행사별 라벨 분기 불필요 |

## 3. 영향
- 사용자 흐름: `/start` → [쉽게 시작] `/quick` 3단계 → `/editor` / [편집기 바로] → `/editor`
- 데이터 모델 변화 없음 (`eventType` 타입이 `'wedding'` 단일 리터럴로 좁아짐)
- 홈·README 문구를 "모바일 청첩장"으로 정리

## 4. 다시 확장할 때
돌잔치 등 다른 행사를 지원하게 되면 새 PRD에서 (1) 선택 UI 위치, (2) 행사별 기본값 구조, (3) `EventType` 확장 및 마이그레이션을 정의한 뒤 헌법 §1.3을 개정한다.
