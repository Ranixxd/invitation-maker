| 항목 | 내용 |

## 1. 배경
기존 흐름은 `홈 → 시작 방법 → (쉽게 시작) → 편집기`였다. 이 흐름에는 두 가지 문제가 있다.
- **"어떤 모양의 청첩장인가"를 고르는 단계가 없다.** 바로 편집은 항상 같은 기본 디자인으로 시작했고, 쉽게 시작은 사진 색으로 테마를 자동 추천했다. 사용자가 원하는 분위기를 먼저 고를 수 없었다.
- **초기 단계에 비해 범위가 넓다.** 홈과 저장(이어서 편집)은 지금 검증하려는 핵심(템플릿 → 편집 경험)과 거리가 있다.

## 2. 결정
| # | 결정 | 대안 | 이유 |
|---|---|---|---|
| D1 | 흐름을 **① 템플릿 선택 → ② 시작 방법(쉽게 시작/바로 편집) → ③ 편집기**로 | 시작 방법 먼저 | 분위기를 먼저 정해야 사진·내용 입력의 맥락이 생김 (청첩장 서비스의 일반적 기대) |
| D2 | 홈 제외, `/`는 `/templates`로 리다이렉트 | 홈 플레이스홀더 유지 | 범위 축소, 진입 즉시 핵심 흐름 |
| D3 | 템플릿 = 테마 프리셋·글꼴·포인트 색·히어로/갤러리 레이아웃·헤드라인 묶음, 6종 | 테마 3종만 | 레이아웃까지 묶어야 템플릿 간 차이가 눈에 보임 |
| D4 | `applyTemplate`은 디자인 값만 덮어쓰고 내용은 보존 | 템플릿별 문구 포함 | 나중에 "템플릿 바꾸기"를 붙여도 내용 손실 없음 |
| D5 | 템플릿 카드 미리보기는 **실제 렌더러 축소**(샘플 데이터) | 정적 썸네일 이미지 | 렌더러 변경이 썸네일에 자동 반영, 이미지 관리 불필요 |
| D6 | 쉽게 시작은 **사진 배치만** 담당(대표 사진·갤러리). 테마 자동 추천 폐지 | 템플릿 위에 추천 테마 덮어쓰기 | 사용자가 고른 템플릿을 존중 |
| D7 | 사진 색은 결과 화면에서 `템플릿 색 / 사진에서 뽑은 색` 선택지로만 제안 | 완전 삭제 | 사진 분석의 가치는 살리되 선택권은 사용자에게 |
| D8 | 템플릿 id는 URL 쿼리(`?template=`)로 단계 간 전달 | 전역 상태 | 새로고침·뒤로가기에도 선택이 유지됨, 상태 단순 |
| D9 | **저장·자동 저장·이어서 편집 제외** — 문서는 메모리에만 | IndexedDB 유지 | 범위 축소. 저장 UX(로컬/서버, 다중 초안)는 별도 설계가 필요 |
| D10 | 저장이 없으므로 편집기 이탈 시 확인 창 + `beforeunload` 경고, `저장 안 됨` 표시 | 경고 없음 | 실수로 작업을 날리는 일 방지 |

## 3. 사용자 흐름
```
/  ─▶ /templates ─(선택)─▶ /start?template=id ─┬─▶ /quick?template=id ─(사진→정보→결과)─┐
          ▲                     │  ▲          └─▶ (바로 편집) ─────────────────────────────┤
          └── 템플릿 바꾸기 ─────┘  └──────── ← / ✕ (확인) ──────── /editor ◀──────────────┘
                                                                     │  ▲
                                                                     ▼  │
                                                                    /view
```
